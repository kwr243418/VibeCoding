# 할 일 관리 앱 PRD

Oct 1, 2026 · @김우림

## 1. 개요

하루 10\~20개의 할 일을 카테고리별로 관리하고 진행률을 한눈에 보는 개인용 웹 앱이다. 설치나 서버 없이 브라우저에서 `index.html`을 열면 바로 동작하고, 데이터는 브라우저의 localStorage에 저장해 새로고침해도 유지된다.

**대상 사용자**: 업무·개인 일정·공부를 함께 챙기는 1인 사용자(본인). 로그인이나 다중 사용자는 고려하지 않는다.

**해결하려는 문제**: 기존 할 일 앱은 기능이 많고 무겁다. 필요한 것은 빠르게 적고, 체크하고, 오늘 얼마나 했는지 확인하는 것뿐이다.

## 2. 목표와 범위

목표는 "5초 안에 할 일을 추가하고, 한 번의 클릭으로 완료하고, 진행률을 항상 볼 수 있는 가벼운 앱"이다.

**목표 (In scope)**

- 할 일 추가·수정·삭제, 완료 체크
- 업무/개인/공부 3개 카테고리 분류와 필터
- 전체 및 카테고리별 진행률 표시
- 새로고침·브라우저 재시작 후에도 데이터 유지

**비목표 (Out of scope, v1)**

- 로그인, 기기 간 동기화, 서버 저장
- 알림, 반복 일정, 하위 할 일
- 프레임워크(React 등)와 빌드 도구

**성공 기준**

| 기준 | 목표치 |
| --- | --- |
| 할 일 1개 추가 소요 시간 | 5초 이내 (입력 + Enter) |
| 새로고침 후 데이터 유실 | 0건 |
| 첫 화면 표시 시간 | 1초 이내 |
| 2주간 실제 사용 | 매일 사용할 만큼 불편함이 없을 것 |

## 3. 사용자 시나리오

하루의 흐름은 아침에 계획하고, 낮에 체크하고, 저녁에 돌아보는 세 단계다.

1. **아침 계획**: 앱을 열고 오늘 할 일 10\~15개를 연속으로 입력한다. 카테고리는 드롭다운에서 고르며, 직전에 고른 카테고리가 유지된다.
2. **낮 실행**: 끝낸 일을 체크박스로 완료 처리한다. 진행률 바가 즉시 올라간다. 오타가 있으면 항목을 더블클릭해 고친다.
3. **저녁 정리**: '업무' 필터로 바꾸어 업무 진행률을 확인하고, 필요 없어진 항목은 삭제한다. 완료한 항목은 "완료 항목 일괄 삭제"로 한 번에 정리한다.

**유저 스토리**

- 사용자로서, 할 일을 키보드만으로 빠르게 추가하고 싶다.
- 사용자로서, 한 번 클릭으로 완료/미완료를 바꾸고 싶다.
- 사용자로서, 카테고리별로 모아 보고 싶다.
- 사용자로서, 오늘 얼마나 했는지 퍼센트로 보고 싶다.
- 사용자로서, 브라우저를 닫았다 열어도 목록이 그대로 있길 원한다.

## 4. 기능 요구사항

v1은 아래 P0 기능 11개로 완성되고, P1은 여유가 있을 때 추가한다.

| ID | 기능 | 상세 동작 | 우선순위 |
| --- | --- | --- | --- |
| F-01 | 할 일 추가 | 제목 입력 + 카테고리 선택 후 Enter 또는 추가 버튼. 공백만 있는 입력은 무시. 최대 100자. 추가 후 입력창 비우고 포커스 유지 | P0 |
| F-02 | 할 일 수정 | 제목 더블클릭(또는 수정 버튼) → 인라인 편집. Enter 저장, Esc 취소. 빈 값으로 저장 시 원래 값 유지. 카테고리도 변경 가능 | P0 |
| F-03 | 할 일 삭제 | 항목별 삭제 버튼. 확인 창 없이 즉시 삭제 | P0 |
| F-04 | 완료 체크 | 체크박스로 완료/미완료 토글. 완료 항목은 취소선 + 흐린 색 | P0 |
| F-05 | 카테고리 분류 | 업무/개인/공부 중 1개 필수. 카테고리별 색상 배지 표시 | P0 |
| F-06 | 카테고리 필터 | 전체/업무/개인/공부 탭. 선택한 필터는 새로고침 후에도 유지 | P0 |
| F-07 | 전체 진행률 | "7 / 12 완료 (58%)" 텍스트 + 진행률 바. 변경 즉시 갱신. 할 일 0개면 0%와 안내 문구 | P0 |
| F-08 | 카테고리별 진행률 | 업무/개인/공부 각각의 완료 수와 퍼센트를 작은 바로 표시 | P0 |
| F-09 | 데이터 자동 저장 | 모든 변경 즉시 localStorage에 저장, 앱 시작 시 불러오기 | P0 |
| F-10 | 완료 항목 일괄 삭제 | 버튼 한 번으로 완료 항목 모두 삭제. 확인 창 표시 | P1 |
| F-11 | 삭제 되돌리기 | 삭제 직후 5초간 "실행 취소" 토스트 표시 | P1 |
| F-12 | 정렬 | 미완료 우선, 그 안에서 추가 순서. 완료 항목은 목록 하단으로 이동 | P1 |
| F-13 | 다크 모드 | 처음에는 운영체제 설정(prefers-color-scheme)을 따름. 헤더의 토글 버튼으로 라이트/다크 직접 전환, 선택은 새로고침 후에도 유지 | P0 |
| F-14 | JSON 내보내기/가져오기 | 내보내기: 전체 할 일을 todo-backup-YYYY-MM-DD.json 파일로 다운로드. 가져오기: JSON 파일을 고르면 형식을 검사한 뒤 "현재 목록을 대체" 확인 후 적용. 잘못된 파일은 안내만 하고 기존 데이터는 그대로 둠 | P0 |

**진행률 계산**: 완료 수 ÷ 전체 수 × 100, 소수점 반올림. 필터를 바꿔도 상단의 전체 진행률은 항상 모든 할 일 기준이다.

## 5. 데이터 모델과 저장

할 일은 객체 배열 하나로 관리하고, 변경될 때마다 배열 전체를 JSON으로 localStorage에 저장한다. 20개 규모면 용량(약 5MB 한도)과 성능 모두 문제가 없다.

**Todo 객체**

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID. `Date.now().toString()` 또는 `crypto.randomUUID()` |
| title | string | 할 일 제목, 1\~100자 |
| category | string | `work` \| `personal` \| `study` |
| completed | boolean | 완료 여부, 기본값 false |
| createdAt | number | 생성 시각(ms), 정렬에 사용 |
| completedAt | number \| null | 완료 시각, 미완료면 null |

**localStorage 키**

- `todo-app:todos` — Todo 배열(JSON)
- `todo-app:filter` — 마지막 선택 필터(`all` | `work` | `personal` | `study`)
- `todo-app:theme` — 사용자가 고른 테마(`light` | `dark`). 값이 없으면 운영체제 설정을 따름

**저장 예시**

```json
[
  {
    "id": "1727740800000",
    "title": "주간 보고서 작성",
    "category": "work",
    "completed": false,
    "createdAt": 1727740800000,
    "completedAt": null
  }
]
```

**예외 처리**: 저장된 값이 없거나 JSON 파싱에 실패하면 빈 배열로 시작한다. 읽기·쓰기는 모두 try/catch로 감싼다.

**백업 파일 형식 (F-14)**: 나중에 형식이 바뀌어도 구분할 수 있도록 버전과 내보낸 시각을 함께 담는다.

```json
{
  "app": "todo-app",
  "version": 1,
  "exportedAt": "2026-10-01T09:00:00.000Z",
  "todos": [ /* Todo 객체 배열 */ ]
}
```

가져올 때는 `app`과 `version`을 확인하고, 각 항목의 필드를 검사한다. title이 없는 항목은 건너뛰고, category가 잘못되면 `work`로, id가 없거나 중복이면 새 id를 붙인다. 테마와 필터 설정은 백업에 포함하지 않는다.

## 6. UI/UX 요구사항

화면은 한 페이지이며, 위에서 아래로 진행률 → 입력 → 필터 → 목록 순서로 배치한다. 최대 폭 600px, 가운데 정렬.

| 영역 | 구성 요소 |
| --- | --- |
| 헤더 | 앱 제목, 오늘 날짜, 다크 모드 토글 버튼 |
| 진행률 패널 | 전체 진행률 바 + "7 / 12 완료 (58%)", 그 아래 카테고리별 작은 바 3개 |
| 입력 영역 | 텍스트 입력창, 카테고리 드롭다운, 추가 버튼 |
| 필터 탭 | 전체 · 업무 · 개인 · 공부 (각 탭에 항목 수 표시) |
| 할 일 목록 | 체크박스 · 제목 · 카테고리 배지 · 수정/삭제 버튼 |
| 하단 | 남은 할 일 수, 완료 항목 일괄 삭제 버튼(P1), JSON 내보내기·가져오기 버튼 |

**카테고리 색상**: 업무 파랑, 개인 초록, 공부 주황. 색만으로 구분하지 않고 배지에 글자도 표시한다.

**다크 모드**: 배경은 완전한 검정 대신 짙은 회색(#1e1e1e 수준)을 쓰고, 카테고리 색은 다크 배경에서도 잘 보이도록 한 단계 밝게 조정한다. 본문 글자와 배경의 대비는 두 테마 모두 4.5:1 이상. 테마가 바뀔 때 화면이 깜빡이지 않도록 페이지 로드 전에 테마를 적용한다.

**인터랙션 규칙**

- 앱을 열면 입력창에 자동 포커스
- 수정/삭제 버튼은 데스크탑에서는 마우스를 올렸을 때, 모바일에서는 항상 표시
- 목록이 비었을 때 "오늘 할 일을 추가해 보세요" 안내 문구
- 모든 동작은 페이지 이동 없이 즉시 화면에 반영
- 모바일(360px 폭)에서도 가로 스크롤 없이 사용 가능

## 7. 기술 요구사항

HTML, CSS, 순수 자바스크립트(ES6+) 3개 파일만 사용하고, 라이브러리·빌드 도구·서버는 쓰지 않는다. `index.html`을 더블클릭하면 바로 실행되어야 한다.

**파일 구조**

```
todo-app/
├── index.html   # 화면 구조
├── style.css    # 스타일
└── app.js       # 상태 관리, 렌더링, 저장
```

**app.js 구성 원칙**

- 상태는 `todos` 배열과 `currentFilter` 변수 두 개로만 관리
- 모든 변경은 "상태 변경 → `save()` → `render()`" 한 방향으로 흐른다
- 주요 함수: `loadTodos`, `saveTodos`, `addTodo`, `updateTodo`, `deleteTodo`, `toggleTodo`, `setFilter`, `getProgress`, `render`
- 목록 이벤트는 항목마다 달지 않고 `<ul>`에 이벤트 위임으로 처리 (`data-id` 속성 사용)
- 사용자 입력은 `innerHTML`이 아닌 `textContent`로 넣어 XSS를 막는다

**지원 브라우저**: Chrome, Edge, Safari, Firefox 최신 버전(데스크톱·모바일). 시크릿/프라이빗 모드에서는 창을 닫으면 데이터가 사라지는 것이 정상이다.

## 8. 비기능 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 성능 | 추가·체크·삭제 후 화면 반영 100ms 이내. 할 일 200개까지 느려지지 않을 것 |
| 접근성 | 키보드만으로 모든 기능 사용(Tab 이동, Space 체크, Enter 저장). 버튼에 `aria-label`, 진행률 바에 `role="progressbar"` |
| 보안 | 사용자 입력은 `textContent`로만 출력 |
| 안정성 | localStorage 사용 불가·용량 초과 시 "저장할 수 없습니다" 안내를 띄우고, 화면에서는 계속 사용 가능 |
| 유지보수 | app.js 300줄 내외, 함수당 한 가지 역할 |

## 9. 개발 단계와 향후 확장

각 단계가 끝날 때마다 브라우저에서 돌아가는 상태를 만든다. 하루 1\~2시간 기준 약 1주 분량이다.

1. **기본 목록**: HTML 레이아웃, 할 일 추가·삭제·완료 체크 (F-01, F-03, F-04)
2. **저장**: localStorage 저장·불러오기, 새로고침 테스트 (F-09)
3. **카테고리**: 카테고리 선택, 배지, 필터 탭 (F-05, F-06)
4. **진행률**: 전체·카테고리별 진행률 바 (F-07, F-08)
5. **수정과 다듬기**: 인라인 수정(F-02), 다크 모드(F-13), 백업(F-14), 스타일, 모바일 대응, 접근성 점검
6. **P1 기능**: 일괄 삭제, 실행 취소, 정렬 (F-10\~F-12)

**v1 완료 체크리스트**

- [ ] 할 일 15개 추가 후 새로고침해도 전부 남아 있다
- [ ] 체크 시 전체·카테고리 진행률이 바로 바뀐다
- [ ] 필터를 바꾼 뒤 새로고침해도 필터가 유지된다
- [ ] 마우스 없이 키보드만으로 추가·완료·삭제가 된다
- [ ] `<script>` 같은 입력이 글자 그대로 표시된다

**향후 확장 아이디어 (v2 이후)**

- 날짜별 기록: 날짜가 바뀌면 미완료 항목을 오늘로 이월하고, 지난 진행률을 보관
- 주간 통계: 요일별 완료율 차트
- 드래그로 순서 변경
- 카테고리 직접 추가·수정
